# V26 数据持久化审计与修复说明

本版专门处理“退出重进后购买日期重置”的风险。

## 修复内容

1. Android SharedPreferences 从 `apply()` 改为 `commit()`，保存时同步确认写盘结果，减少保存后立即退出导致写入未落盘的风险。
2. Flutter `LocalJsonStorage.save()` 不再吞掉保存异常；如果原生保存返回失败，会抛出错误，便于后续定位。
3. 资产编辑页保存资产时改为 `await store.upsertAsset(item)`，确保本地保存完成后再返回上一页。
4. 新建资产/心愿页保存时也改为等待本地保存完成。
5. `Asset.fromMap()` 不再在日期解析失败时静默使用“今天”。购买日期会优先读取 `purchaseDate`，失败时回退到 `createdAt`，再失败才使用 1970-01-01 作为异常标记，避免每次启动都变成当天。
6. 日期读取新增 `parsePersistedDate()` 与 `parseOptionalPersistedDate()`，把“用户正在输入表单时可以用今天兜底”和“从持久化数据恢复时不能用今天兜底”分开。

## 风险说明

如果旧版本已经把某些资产的购买日期覆盖成了今天，本版不能自动知道用户原来输入过什么日期，只能防止后续继续重置。若有云端备份/JSON 备份里仍然是旧日期，可以通过备份恢复找回。

## 其他数据是否有类似问题

本次重点检查了资产、心愿、分类、标签、设置、快照和云端同步字段。最大风险集中在日期字段，因为旧逻辑在解析失败时会默认使用当天。普通文本、价格、分类、标签一般不会自动变成默认值，除非本地 JSON 被云同步旧备份覆盖，或保存未完成就强制退出。
